## Features Added

### 1. Habits / Projects two-section grid

Split the main grid view into two labeled, independently scrollable sections — **Habits** (top) and **Projects** (bottom) — separated by a horizontal divider.

**Schema change (`shared/schema.ts`)**
- Added `itemType TEXT NOT NULL DEFAULT 'habit'` column to the `habits` table. Values: `"habit"` | `"project"`.
- Added `itemType: true` to `insertHabitSchema` picks.

**Storage (`api/storage.ts`)**
- `copyHabitsToMonth` now carries `itemType` through when copying habits across months.

**API (`api/routes.ts`)**
- `POST /api/habits` accepts `itemType` via the existing `insertHabitSchema` validation; no other route changes needed.

**Frontend**
- `Habit` interface in `HabitTracker.tsx` gains `itemType?: "habit" | "project"`.
- `handleAddHabit` accepts a `type: "habit" | "project"` parameter (default `"habit"`) and passes it to the create mutation.
- `HabitGrid.tsx` fully rewritten to render two sections. Each section has its own `DndContext`, `SortableContext`, `ScrollArea`, header row, rows filtered by `itemType`, and add button. The name-column collapse state is shared between sections. Reordering within a section sends the full combined ID list (section items + other section items) so `sortOrder` stays coherent.
- `HabitRow.tsx` gains an optional `placeholder` prop forwarded to `HabitNameInput`, used to show "New project..." instead of "New habit..." in the projects section.

**`db:push` required** to apply the `item_type` column.

### 2. Per-section month notes

Added a full-width auto-growing textarea beneath each section's add button for free-form monthly notes.

**Schema change (`shared/schema.ts`)**
- New `month_notes` table: `id`, `userId` (FK → users, cascade delete), `month` (YYYY-MM), `section` ("habit" | "project"), `content` (text), `updatedAt`.
- Unique index on `(userId, month, section)` to support upsert.

**Storage (`api/storage.ts`)**
- `getMonthNote(userId, month, section)` — returns the note row or undefined.
- `upsertMonthNote(userId, month, section, content)` — insert or update via `onConflictDoUpdate`.

**API (`api/routes.ts`)**
- `GET /api/notes?month=YYYY-MM&section=habit|project` — returns `{ content: string }`.
- `PATCH /api/notes` body `{ month, section, content }` — upserts the note, responds 204.

**Frontend — `MonthNoteInput.tsx` (new component)**
- Fetches the saved note on mount (and whenever month or section changes).
- Auto-grows textarea height to fit content via `scrollHeight` on each render.
- **Enter** blurs the field (triggering a save); **Shift+Enter** inserts a newline.
- Saves to the API on blur.
- Disabled + low opacity while the initial fetch is in flight.

**`db:push` required** to apply the `month_notes` table.

### 3. Copy-habits dialog mobile fix

The dialog was clipped on the right and the action buttons were off the bottom of the screen on phones because the habit grid's horizontal overflow inflated the document width beyond the viewport.

**`CopyHabitsDialog.tsx`**
- Added `max-w-[calc(100vw-2rem)]` — clamps dialog width to true viewport width with a small margin.
- Added `flex flex-col max-h-[90svh] overflow-hidden` — caps total dialog height at 90% of the small viewport height (reliable on mobile where the browser chrome collapses).
- Middle content div: `flex-1 min-h-0 overflow-y-auto` — habit list scrolls within the available space.
- Header and footer marked `shrink-0` so they are always fully visible.
- Removed the `max-h-64 overflow-y-auto` constraint from the inner habit list (parent now handles scrolling).
