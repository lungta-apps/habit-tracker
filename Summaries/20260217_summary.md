## Feature Implemented

### Drag-and-Drop Habit Reordering (Grid View)

Users can now reorder habits by dragging the GripVertical handle on the left side of each habit row. The new order is saved to the database and persists across sessions.

**Interaction model:**
- Grab the GripVertical icon (left of color picker) to initiate drag
- Drag up/down to reposition; other rows shift to show drop target
- A floating overlay shows the habit name/color while dragging
- Release to drop; order is saved immediately via optimistic update
- Order persists per-month (each month has independent ordering)

## Bugs Encountered & Fixed

### 1. Express route ordering (main blocker)
`PATCH /api/habits/reorder` was initially registered AFTER `PATCH /api/habits/:id`. Express matched the parameterized route first, capturing `"reorder"` as the `:id` value, returning 404. The mutation's `onError` rolled back the optimistic update, causing habits to "bounce back" to their original position. **Fix:** Moved the reorder route before the parameterized route.

### 2. CSS subgrid incompatibility with dnd-kit
HabitRow originally used `display: contents` (no bounding box for dnd-kit). The plan called for CSS subgrid (`grid-column: 1 / -1; display: grid; grid-template-columns: subgrid`), but dnd-kit's `verticalListSortingStrategy` couldn't properly measure/sort items inside a shared CSS Grid context. **Fix:** Each HabitRow is now a plain block-level div containing its own independent grid, with the same column template as the header.

### 3. Async optimistic update timing
The initial `onMutate` used `async/await` for `cancelQueries`, pushing `setQueryData` into a microtask after dnd-kit cleared transforms. **Fix:** Made `onMutate` synchronous (fire-and-forget `cancelQueries`) so the cache update batches with dnd-kit's state clearing.
