## Features Added

### 1. Per-week frequency goals

Habits and projects can now have an optional weekly frequency target (1–6 times per week) instead of implying a daily goal. This is useful for habits like "work out 4×/wk" where the specific days vary week to week.

**Schema (`shared/schema.ts`)**
- Added `weeklyTarget: integer("weekly_target")` (nullable) to the `habits` table. `null` = daily habit (existing behavior); `1–6` = times-per-week goal.
- Added `weeklyTarget: z.number().int().min(1).max(7).nullable().optional()` to `updateHabitSchema` so the PATCH endpoint accepts it with no other route changes needed.
- `db:push` run to apply the `weekly_target` column.

**Frontend — `HabitTracker.tsx`**
- `Habit` interface gains `weeklyTarget?: number | null`.
- `updateHabit` API function and `updateMutation` type updated to accept `weeklyTarget`.
- New `handleUpdateHabitWeeklyTarget(id, target)` callback — reuses the existing update mutation.
- `HabitGrid` receives `onUpdateHabitWeeklyTarget` prop.

**Frontend — `HabitNameInput.tsx`**
- New props: `weeklyTarget?: number | null`, `onWeeklyTargetChange?: (target: number | null) => void`.
- A chip rendered between the text input and delete button:
  - When no target is set: faint `···` visible only on row hover.
  - When a target is set: solid `Nx/wk` label, always visible.
- Clicking the chip opens a controlled shadcn `Popover` (closes automatically on selection) listing `1×/wk` through `6×/wk`. No "Daily" option — currently no in-grid way to clear a target once set.

**Frontend — `HabitRow.tsx`**
- New props: `weeklyTarget`, `onWeeklyTargetChange`, `sundayDays: Set<number>`.
- Computes week ranges from `sundayDays`, then maps each day to its week's completion count.
- `gridTemplateColumns` interleaves 20px separator columns after each Sunday.
- After each Sunday's day cell, renders a separator cell:
  - For habits with a `weeklyTarget`: a segmented bar — `weeklyTarget` equal-height segments divided by `border-b` lines, filling white (`bg-white/80`) from the bottom up as completions accumulate. Empty segments are `bg-zinc-900`.
  - For habits without a target: the separator column is present but the cell is empty.
- Passes `weeklyTarget` / `onWeeklyTargetChange` to `HabitNameInput` and `isWeekGoalMet` to each `HabitCell`.

**Frontend — `HabitGrid.tsx`**
- Accepts `onUpdateHabitWeeklyTarget` prop.
- Computes `sundayDays: Set<number>` via `useMemo` — days in the month that fall on Sunday, excluding the last day (so no trailing separator). Passed to all `HabitRow` instances so every row uses the same grid template.
- `gridTemplate` updated to interleave `20px` separator columns after each Sunday, keeping `dayLettersRow` and `headerRow` in sync with the habit rows. Both use `Fragment` to emit separator divs at the right positions.

**Frontend — `HabitCell.tsx`**
- New prop: `isWeekGoalMet?: boolean`.
- When `isWeekGoalMet && !isCompleted`: cell renders with `bg-zinc-900/60` tint and a `—` dash, distinguishing "optional this week" from the normal empty state.

### 2. Time Block Planner — resize handle visuals removed

The semicircular resize handle indicators were visually cluttered. The visible shapes were removed; the invisible touch zones (`absolute -top-3`/`-bottom-3`, `h-6`) remain so resizing still works by grabbing the block edge.

**`TimeBlockCalendar.tsx`**
- Removed the inner `<div className="w-6 h-3 rounded-t-full bg-white/50 ...">` and `rounded-b-full` elements from both handle divs.
- Touch zone divs are now self-closing, no children.

---

### 3. Time Block Planner — inset glow block styling

Replaced the solid colored fill on time blocks with a transparent interior and an inset colored glow, so adjacent blocks don't bleed into each other visually.

**`TimeBlockCalendar.tsx`**
- Replaced `BLOCK_BG` (Tailwind bg class map) with `BLOCK_GLOW_COLOR` (CSS `rgba()` string map) — required because `box-shadow` needs actual color values, not Tailwind class names.
- Inner block div: changed from `className={bgClass}` to `className="bg-black/40"` + `style={{ boxShadow: \`inset 0 0 12px 4px ${glowColor}\` }}`.
- The `inset` keyword keeps the glow fully inside the block's own boundary.
