## 1. Resize handle redesign — semicircles on the outer edge

**Before**: Top and bottom resize handles were flat pill-shaped bars rendered *inside* the block (h-4 zones at top and bottom, with a `w-6 h-1 rounded-full` indicator). The bottom handle container had `bg-white/10`, causing a visibly lighter strip at the bottom of every block.

**After**: Handles are small semicircles that protrude *outside* the block's top/bottom edges, matching the design in the reference photo.

**How it works**:
- The outer block `<div>` no longer has `overflow-hidden` (so handles can extend outside the bounds).
- A new inner `<div className="absolute inset-0 rounded-md overflow-hidden {bgClass}">` holds the background color, action bar, and block content — keeping rounded corners intact.
- Top handle: `absolute -top-3 h-6` touch zone, visual is `w-6 h-3 rounded-t-full bg-white/50` — flat side flush with the block's top edge, rounded part above.
- Bottom handle: `absolute -bottom-3 h-6` touch zone, visual is `w-6 h-3 rounded-b-full bg-white/50` — flat side flush with the block's bottom edge, rounded part below.
- Removing `bg-white/10` from the old bottom handle container also eliminated the darker-shade artifact at the bottom of each block.

## 2. Bounce fix — block snaps to new position without flickering

**Symptom**: After dragging a block (move or resize) to a new time and releasing, the block would briefly jump back to its original position before landing at the new time. Affected both resize handles and full-block moves.

**Root cause**: `handlePointerUp` called `setDragOverride(null)` and `onUpdateBlock(...)` in the same render. Clearing the override removed the visual position immediately, so the block rendered at its original position for one frame. The block then jumped to the correct position only after the TanStack Query mutation completed and the `blocks` prop updated from the server.

**Fix**:
- `handlePointerUp` no longer calls `setDragOverride(null)` for normal drops. The override stays in place, holding the block at the dropped position while the mutation is in flight.
- A new `useEffect` watches `blocks` and clears `dragOverride` only once the server-updated block matches the committed position — at that point the block is already rendered correctly, so there is no visible jump.
- `handlePointerCancel` still clears `dragOverride` immediately (drag aborted — block should revert).

```ts
// New useEffect — clears override once server data catches up
useEffect(() => {
  if (!dragOverride || dragState) return;
  const block = blocks.find((b) => b.id === dragOverride.blockId);
  if (
    block &&
    block.startMinute === dragOverride.startMinute &&
    block.durationMinutes === dragOverride.durationMinutes
  ) {
    setDragOverride(null);
  }
}, [blocks, dragOverride, dragState, setDragOverride]);
```

## 3. Long-press grab reliability

**Symptom**: Grabbing a placed block to move it worked inconsistently — sometimes the long-press activated, other times it silently cancelled.

**Root cause**: `LONG_PRESS_CANCEL_DISTANCE` was 8px. A finger naturally drifts 8–10px just from the act of pressing down, causing the cancel threshold to be exceeded before the 400ms timer fired.

**Fix**:
- `LONG_PRESS_CANCEL_DISTANCE`: 8 → **14px** — enough tolerance for natural finger drift without being so loose that intentional scroll is mistaken for a hold.
- `LONG_PRESS_MS`: 400 → **300ms** — activates faster so the grab feels more responsive.
